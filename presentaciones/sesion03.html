¿Cómo sabe una máquina de compilación si un paso terminó bien o falló?

Objetivo de hoy

Escribir y leer archivos desde C y devolver códigos de salida POSIX, para que un pipeline de compilación pueda encadenar pasos y detenerse ante un error.

Al terminar tendrás

Tres funciones en C que escriben y leen archivos y que reportan el código de salida real de un comando externo.

Antes de los tecnicismos: los conceptos básicos

Si te quedas con estas ideas, el resto de la sesión se entiende solo.

01. Código de salida

El número que un programa devuelve al sistema operativo al terminar; 0 significa éxito.

Analogía: Como el semáforo al final de un trámite: verde (0) o te regresan a ventanilla.

02. stdout y stderr

Dos canales de salida: uno para el resultado y otro para los mensajes de error.

Analogía: Como la banda de equipaje y la oficina de reclamos: no mezcles tu maleta con las quejas.

03. Archivo como recurso

Abrir, leer o escribir y cerrar: el archivo se pide prestado y hay que devolverlo.

Analogía: Como un libro de biblioteca: si no lo devuelves, nadie más puede usarlo.

04. Bandera -Werror

Convertir cualquier advertencia del compilador en un error que detiene la compilación.

Analogía: Como el detector de humo que corta la energía: molesto, pero evita el incendio.

¿Dónde estamos y a dónde vamos?

Un compilador es una herramienta de línea de comandos: recibe un archivo, escribe otro y devuelve un número. Ese número (0 = éxito, distinto de 0 = error) es lo que permite que make, GitHub Actions o un script encadenen pasos. Sin él, nadie sabe si el paso anterior funcionó.

00–20 min: Fundamentos teóricos — Automatización de Compiladores en Entornos Linux

Un compilador se ejecuta como una herramienta de línea de comandos (CLI) sujeta a convenciones POSIX y códigos de retorno.

01. Comandos Mágicos %%writefile[+]

Colab permite volcar el contenido de una celda directamente al sistema de archivos virtual de Linux.

Permite crear módulos .c, .rs y scripts de prueba limpios y reproducibles.
02. Códigos de Salida ABI (Exit Codes)[+]

El valor retornado por main() (return 0; vs return 1;) indica al sistema si la compilación fue exitosa.

Un compilador que falla debe retornar un código distinto de cero para detener el pipeline de construcción.
03. Banderas Estrictas de GCC[+]

Compilar con -Wall -Wextra -Werror convierte cualquier advertencia de tipos o punteros en un error fatal.

Evita que errores sutiles de compilación pasen desapercibidos a fases posteriores.

Arquitectura de memoria y estructuras de datos: Llamadas al Sistema y Flujos Estándar

Separación de flujos para diagnósticos limpios:

stdout vs stderr[+]

El código generado se emite a stdout (1); los mensajes de error semántico deben enviarse a stderr (2).

Permite redirigir el código objeto generado sin contaminarlo con logs de depuración.
Tuberías (Pipes POSIX)[+]

La salida de un pase del compilador alimenta la entrada del siguiente: scanner | parser | codegen.

Reduce el acceso a disco intermedio manteniendo los datos en memoria compartida.

Puntos de Falla en el Pipeline

Puntos críticos de falla que debes proteger en tu código y auditar en las respuestas del LLM:

  • Escribir logs de depuración en stdout rompiendo la generación del archivo ensamblador.
  • Ignorar advertencias de conversión de tipos enteros con signo a no signo.
  • No limpiar archivos binarios previos generando pruebas falsas positivas con binarios obsoletos.

Lo que vas a construir hoy

Tu programa escribe un archivo de texto y luego cuenta sus líneas. El harness prueba los tres casos que rompen a casi todos: archivo sin salto final, archivo vacío y ruta inexistente.

Entregable

tus funciones en artesano_sesion03_c.c, el harness en verde y la bitácora de la sesión

Reglas del reto
  • Usa fopen/fgetc o fgets y cierra siempre el archivo.
  • Un archivo inexistente se reporta con -1, no con un aborto.
  • Una última línea sin salto de línea también cuenta.
Se acepta cuando
  • Los archivos se cierran en todos los caminos y un error se reporta con -1.
  • contar_lineas distingue un archivo vacío, uno con salto final y uno sin él.
  • escribir_texto falla con -1 si la ruta no se puede abrir.
