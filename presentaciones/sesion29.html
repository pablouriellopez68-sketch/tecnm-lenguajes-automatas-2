Optimización: Eliminación de Código Muerto (Dead Code Elimination)

¿Cómo distingue un compilador el código que nunca se ejecutará del que sí importa?

Objetivo de hoy

Detectar instrucciones inalcanzables después de un GOTO o un RETURN y compactar la lista de cuádruplos conservando las etiquetas.

Al terminar tendrás

Una función en C que elimina instrucciones inalcanzables y devuelve el nuevo tamaño de la lista.

Antes de los tecnicismos: los conceptos básicos

Si te quedas con estas ideas, el resto de la sesión se entiende solo.

01. Código inalcanzable

Instrucciones que el flujo de control no puede ejecutar porque un salto o un retorno las deja atrás.

Analogía: Como una puerta tapiada al final del pasillo: sigue dibujada en el plano, pero nadie puede pasar por ella.

02. Etiqueta destino

Marca que puede recibir el control desde otra parte y, por lo tanto, reinicia la zona alcanzable.

Analogía: Como una estación de transbordo: aunque el tren anterior terminó, aquí puede llegar otro.

03. Barrido

Recorrer la lista y conservar solo las instrucciones que el flujo puede alcanzar.

Analogía: Como limpiar una fila de sillas: te llevas solo las que nadie va a usar y dejas las ocupadas.

04. Punto de retorno

Instrucción RETURN que corta el flujo actual y hace inalcanzable lo que sigue hasta una etiqueta.

Analogía: Como el final de una carta: después de la firma, lo que escribas ya no forma parte del mensaje.

¿Dónde estamos y a dónde vamos?

El generador de código puede producir instrucciones después de un salto que nunca se alcanzan. Dejarlas no cambia el resultado, pero infla el binario y confunde al asignador de registros. La regla es simple: tras un salto incondicional, todo es inalcanzable hasta la siguiente etiqueta.

00–20 min: Fundamentos teóricos — Detección de Instrucciones Inalcanzables y Variables Huérfanas

Elimina instrucciones que calculan valores nunca leídos o que residen en bloques inalcanzables.

01. Instrucciones Inalcanzables (Unreachable Code)[+]

Código colocado inmediatamente después de un 'GOTO' o 'RETURN' sin una etiqueta intermedia.

Se eliminan de forma segura ya que el flujo de ejecución nunca puede alcanzarlas.
02. Variables Muertas (Dead Variables)[+]

Asignaciones a temporales o variables locales que nunca vuelven a leerse antes de ser sobrescritas o salir de ámbito.

Reduce la presión sobre los registros de CPU en el backend.
03. Poda de Ramas Condicionales Muertas[+]

En 'if (0) { ... }' o 'if (1) { ... }', el optimizador elimina la rama que nunca se ejecutará y el salto condicional.

Convierte bifurcaciones complejas en código secuencial directo.

Arquitectura de memoria y estructuras de datos: Análisis de Alcance y Grafo de Flujo (Reachability)

Algoritmo de marcado y barrido sobre el CFG:

Grafo de Bloques Básicos[+]

Se construye un grafo dirigido donde cada nodo es un bloque básico y las aristas son saltos.

Un recorrido BFS/DFS desde el bloque inicial marca todos los bloques alcanzables.
Barrido de Instrucciones Huérfanas[+]

Cualquier bloque no marcado como alcanzable se desvincula y se libera de la memoria de cuádruplos.

Reduce significativamente el tamaño del binario final.

Antipatrones en Eliminación de Código

Puntos críticos de falla que debes proteger en tu código y auditar en las respuestas del LLM:

  • Eliminar una instrucción con efectos secundarios (como llamadas a funciones de I/O) creyendo erróneamente que es código muerto.
  • Borrar etiquetas que son destinos de saltos indirectos o tablas de saltos (switch).
  • Romper punteros de la lista de cuádruplos al desvincular un nodo eliminado.

Lo que vas a construir hoy

Recibes un arreglo con n instrucciones TAC y debes compactarlo en el mismo arreglo. Conserva todo hasta un GOTO o RETURN y descarta lo que sigue hasta la próxima etiqueta; devuelve cuántas instrucciones quedaron.

Entregable

tu función eliminar_muerto() en artesano_sesion29_c.c, el harness en verde y la bitácora en auditorias/auditoria_sesion29.md

Reglas del reto
  • Una etiqueta termina en dos puntos y siempre es alcanzable: corta la zona muerta.
  • El GOTO y el RETURN se conservan; solo se descarta lo que viene después.
  • Compacta en el mismo arreglo y no cambies el orden de las instrucciones que sobreviven.
Se acepta cuando
  • Toda instrucción posterior a un GOTO o RETURN se descarta hasta la próxima etiqueta.
  • Las etiquetas y las instrucciones alcanzables conservan su orden original.
  • Una lista vacía devuelve 0 sin leer memoria fuera del arreglo.
