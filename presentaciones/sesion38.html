Enlace (Linking) y Creación de Binarios Ejecutables ELF

¿Qué ocurre entre el archivo .s y el programa que finalmente corre en Linux?

Objetivo de hoy

Seguir el recorrido as, .o, ld/gcc, ELF y comprobar dos resultados observables: símbolos sin resolver y el código de salida que ve el shell.

Al terminar tendrás

Dos funciones: una que predice el $? de un main y otra que cuenta los símbolos que el enlazador todavía debe resolver.

Antes de los tecnicismos: los conceptos básicos

Si te quedas con estas ideas, el resto de la sesión se entiende solo.

01. Archivo objeto

El .o que produce as: instrucciones máquina más una tabla de símbolos que aún puede tener referencias pendientes.

Analogía: Como una mudanza a medio hacer: las cajas están cerradas pero algunas llevan la etiqueta de dirección desconocida.

02. Símbolo indefinido

Un nombre que el .o usa pero no define, como printf o malloc, y que el enlazador debe resolver.

Analogía: Como una llamada a un proveedor que todavía no está en tu agenda: hay que buscarlo antes de usarlo.

03. ELF

El formato de archivo que Linux reconoce para ejecutables y objetos; declara secciones, símbolos y puntos de entrada.

Analogía: Como el pasaporte de un programa: sin él, el sistema no lo deja entrar.

04. Código de salida

El byte bajo del valor que main devuelve; el shell lo expone en $?.

Analogía: Como el resumen de una factura: ves el total redondeado, no el detalle completo de cada centavo.

¿Dónde estamos y a dónde vamos?

Un compilador no termina cuando escribe ensamblador: termina cuando el binario se ejecuta. El enlazador conecta tu call printf con la biblioteca real y tu main con crt1.o; si falta un símbolo, no hay binario. Además, el $? que revisa el script de pruebas no es el return completo de main, sino su byte bajo, algo que confunde a cualquiera que audita.

00–20 min: Fundamentos teóricos — Ensamblado con AS y Enlace con GCC / LD

El archivo ensamblador '.s' se convierte en código máquina reubicable '.o' y finalmente en un ejecutable ELF.

01. El Ensamblador (as)[+]

Traduce las instrucciones mnemónicas ('movq', 'addq') a bytes de código máquina hexadecimales.

Genera un archivo objeto en formato ELF (Executable and Linkable Format) con símbolos no resueltos.
02. El Enlazador (Linker / ld)[+]

Resuelve direcciones de funciones externas ('printf', 'malloc', 'exit') y conecta el código de inicio de C (crt1.o).

Produce el binario ejecutable final autónomo.
03. Invocación desde GCC[+]

El comando 'gcc salida.s -o binario_final' coordina automáticamente el ensamblado y enlace.

Incluye las rutas de búsqueda de bibliotecas estándar sin necesidad de llamar a 'ld' manualmente.

Arquitectura de memoria y estructuras de datos: Estructura del Binario ELF en Linux

Segmentos de memoria cargados por el núcleo del sistema operativo:

Segmentos ELF[+]

Segmento de Texto (.text, solo lectura/ejecución), Datos (.data/.rodata, lectura/escritura) y Pila (Stack).

El cargador de Linux (ELF Loader) mapea estos segmentos en el espacio de direcciones virtuales.
Código de Salida ($?)[+]

El valor devuelto por 'main()' en RAX se pasa al sistema operativo como exit code del proceso.

Verificable en consola mediante 'echo $?'.

Puntos de Falla en el Enlace

Puntos críticos de falla que debes proteger en tu código y auditar en las respuestas del LLM:

  • Error 'undefined reference to main': no declarar el punto de entrada global.
  • Incompatibilidad de arquitectura: intentar compilar código de 32 bits en modo de 64 bits sin banderas multilib.
  • Permisos de ejecución no asignados en el binario resultante ('chmod +x').

Lo que vas a construir hoy

Recibes un valor de retorno de main o una tabla de símbolos con marca :U o :T; devuelves el código de salida que verá el shell o cuántos símbolos siguen indefinidos.

Entregable

tu implementación de codigo_salida() y simbolos_sin_resolver() en artesano_sesion38_c.c, el harness en verde y la bitácora en auditorias/auditoria_sesion38.md

Reglas del reto
  • El código de salida es retorno & 0xFF: los valores negativos y los mayores que 255 se recortan.
  • En la tabla, cada símbolo es un token separado por espacios y termina en :U (indefinido) o :T (definido).
  • Una tabla vacía no tiene símbolos indefinidos; un token que no termina en :U tampoco se cuenta.
Se acepta cuando
  • codigo_salida reproduce el recorte a 8 bits que hace el sistema operativo con el retorno de main.
  • simbolos_sin_resolver cuenta solo los tokens terminados en :U y tolera cadenas vacías.
  • Los seis casos del harness salen OK y el programa termina con código de salida 0.
